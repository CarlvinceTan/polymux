The previous HTML recreation was visually approximate despite passing its interaction tests. The new native-surface guard failed against that implementation before it was replaced. Captures now come from the unchanged native views through the DEBUG-only `SiteFixture`; both the fixture and the website use `src/content/demo.json`. This removes the duplicated UI rather than adding another styling reminder.

Capture geometry comes from native accessibility `screenshot_frame` bounds, including the close control used as the focus probe. `src/assets/app-demo/manifest.json` records the fixture and image hashes. Run the app with `scripts/run.sh --fixture --verify-site --verify-dark -AppleInterfaceStyle Dark`. Obtain explicit approval before briefly focusing the isolated app, verify the exact window is focused through Cua MCP, and check it remains active before each capture. Restore the user's prior window immediately afterward. Record `windowState: focused` and `focusProbe` bounds in `native-geometry.json`, then encode with `python3 apps/site/scripts/prepare-demo.py <capture-directory>`. The capture dependency is pinned in `scripts/requirements.txt`; install it in a virtual environment. Do not substitute a SwiftUI appearance override: the AppKit titlebar glass must also be genuinely focused.

The guard protects the recorded states and their source pixels, not a continuously running native UI. Recapture and compare after relevant native UI changes. Responsive scaling and browser focus outlines are website presentation; Zoom retains the native logical size. No CSS recreates native glass.

Browser checks at 320, 390, 768, and 1280px verified selection, native-size Zoom, contained mobile panning, Close/Escape, keyboard reopening after focus restoration, and readable transcripts. The native `fixture-site.js` flow passed through Cua MCP without taking focus. `npm run check`, all 44 site tests, and the production build passed on 2026-10-23.

The focused capture refresh was verified in the website at native scale. All 21,824 sampled toolbar pixels and 7,040 call-button pixels matched the native PNG exactly. Of 8,000 sampled header pixels, two coloured avatar-edge pixels differed by 1/255 in a channel. Earlier PNG and WebP comparisons exhibited the same kind of browser colour rounding. Browser rounding is outside the lossless asset guarantee; do not claim identical final display pixels on every browser, scale, or display.

## Source ownership

- `src/content/` owns authored Markdown, product data, legal HTML, and site metadata. Keep `demo.json` at its current path: the native fixture consumes the same bytes.
- `src/pages/` colocates page components, browser entrypoints, and page styles. `src/components/` owns shared layouts and controls; `src/styles/` owns tokens, resets, navigation, and prose styling.
- `lib/content/` owns pure parsing and validation; `lib/server/` owns API behavior. Both use the identity and URL helpers in `lib/site.ts`.
- `scripts/prepare.ts` validates one manifest before generating every HTML entry under `.generated/pages/` and API release metadata at `.generated/releases.json`. `.generated/` is disposable and ignored; there are no authored HTML entry shells or root-level route directories.
- The Vite plugin uses `.generated/pages/` as its HTML root while resolving browser source from `src/` and static assets from `public/`. It prerenders from the manifest and emits `sitemap.xml`, `llms.txt`, and `llms-full.txt` into `dist/`. Development regenerates content, metadata, and routes on changes.
- `/privacy-policy/` owns the full policy; `/privacy/` permanently redirects there. The removed CMS is not shipped, and its URLs return 404.
- Preview reads `_site/manifest.json` and static machine docs from the build output. It never prepares newer source content over an older build.
- `npm run vercel-build` prepares only server release metadata using production dependencies, independently of the frontend build. This is Vercel's custom function-build hook; generated metadata is never committed.
- `npm run verify` runs tests, type checks across browser/build/server code, and a production build. Tests use temporary outputs and servers; nested source checks are recursive.

## Refactor verification

On 2026-10-24, an isolated Chrome profile was operated through native Cua MCP without taking focus from Safari. Documentation was inspected at 1280 and 500px window widths; Chrome's native minimum prevented a 390px window. Search and navigation, the documentation dialog's Escape behavior, release selection and arrow-key focus, and demo selection/Zoom/Escape/focus restoration were exercised. The browser and preview server were closed afterward.

Rendered screenshots contained the shared text and focus colours. The weakest sampled text/background pair was 6.99:1; control outlines were at least 5.10:1. The website has one fixed dark theme, independent of OS appearance. This does not claim every hover/disabled state or a 320px rendered check.

Final checks on 2026-10-24: all 62 tests passed twice after isolating SSR caches; `npm run verify` passed browser/build/server type checks with zero errors or warnings and built all 27 public pages plus the CMS. `npm run vercel-build`, capture-tool help, and `git diff --check` passed; `npm audit` reported zero known vulnerabilities. No production deployment or authenticated CMS write was performed.
